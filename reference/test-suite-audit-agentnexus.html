Test Suite Audit — Against the Nine-Lesson Curriculum

Audited 2026-08-24 · Scope: tests/ (66 files, ~7,450 lines) + CI workflow · Rubric: Lessons 1–9

Executive verdict

Shape: a healthy-looking pyramid on paper — 56 unit files (~6,600 lines), 6 integration files (~650 lines), 0 E2E tests, 2 property files. But measured against this codebase's actual risk (infra-heavy FastAPI: PostgreSQL, Redis, MongoDB, Celery, WebSockets, LangGraph), the mass sits too high on pure units and too thin at the seams. This is a pyramid drifting toward the Testing Trophy's diagnosis: most of your real risk lives at boundaries your suite barely touches [L4, L6].

Culture: unusually self-aware. Your own conftest.py documents why stubs were removed and what defect they were hiding — that's senior behavior most suites never exhibit. The problems below are localized, not systemic.

2. What's genuinely good (keep these)

  • Marker taxonomy + strict markers (pyproject.toml): --strict-markers with slow/integration/unit/requires_db, default-deselecting integration locally — fast inner loop, explicit opt-in [L1 speed trait].
  • CI ordering (.github/workflows/test.yml): lint → format → unit → integration → coverage. Fast gates first, exactly the L9 gate ladder.
  • The retry-policy test's sleep interception (tests/unit/shared/langgraph_layer/test_kb_retry_policy.py:52): intercepts the sleeper instead of sleeping — the exact pattern L5/L8 demand. This file is the house style for time-dependency testing.
  • Self-documenting fixture surgery: both conftests explain why stubs exist, cite commits (319c698, 6525c6f), and record the caught defect. Rare and valuable.
  • Patch-at-binding-site discipline (test_parser_offload_and_tables.py:109-116): monkeypatches where the name is bound, with a docstring teaching why — implementation-coupling avoided correctly.
  • Assert messages where stakes are high (capacity overflow message, test_websocket_security_bug_conditions.py:231).
  • Property-based tests for credit invariants — beyond-curriculum maturity.

3. Anti-patterns found (named per Lesson 8)

3.1 Wall-clock dependency in unit tests — flakiness by construction

LocationWhat happens
tests/unit/test_websocket_security_bug_conditions.py:156await asyncio.sleep(2) to let a Redis TTL lapse — even though expires_at was already set one second in the past at line 150. The sleep likely guards nothing the data doesn't already encode.
tests/unit/test_websocket_security_preservation.py:116await asyncio.sleep(0.1) as synchronization hope.
tests/unit/features/documents/test_parser_offload_and_tables.py:94time.sleep(0.15) inside a fake converter to simulate blocking — deliberate, but still wall-clock.

3.2 Swallowed exceptions make a test passable-for-the-wrong-reason

test_websocket_security_bug_conditions.py:225 — the TOCTOU capacity test wraps connection attempts in except Exception: rejected += 1. Any bug — TypeError, AttributeError, a typo in the service — counts as a "rejection," and the test can go green while the capacity guard is completely broken. Combined with the loop-and-counter structure, this is logic-in-tests [L2] plus assertion roulette [L8]: two failure modes hiding one real assertion.

3.3 Bare assert True — a test verifying nothing

tests/integration/test_websocket_security_integration.py:324 ends with a literal assert True after calling touch_connection() three times. The comment admits it: "This is hard to test directly." But throttling IS observable through the boundary you already have — read Redis before and after rapid touches and assert the last-touch timestamp did not advance on calls two and three. The infrastructure to observe it is in the same file.

3.4 Tautological and near-empty assertions

  • tests/unit/test_agent_saul_persist_memory.py:75: assert result["status"].value == "completed" or result["status"] == "completed" — an OR-assert passes if either representation holds; it can't distinguish a real enum from an accidentally-stringified one. Normalize the result once, assert once.
  • Same file, lines 92 & 100: assert ... is not None — presence-only checks where the lesson rubric asks for the value [L1: behavior-focused assertions].

3.5 Private reach-ins — implementation coupling in unit tests

test_websocket_security_bug_conditions.py:159,180: assigns ws_security_service._token_repo = token_repo and calls _check_session_validity(...) directly. Two underscore-deep privates in one test = the test breaks on refactor regardless of behavior [L2's core trap]. Drive through the public method that performs session checks on message receipt.

3.6 Mock discipline: 104 bare MagicMocks, 2 specs

Repo-wide: MagicMock( appears 104×; spec= appears 2×. The starkest contrast is inside one file: conftest.py:84 builds the auth service with MagicMock(spec=UserRepository) (correct!), while make_mock_user() at line 88 returns a bare MagicMock — so every auth test would pass even if the real User model renamed hashed_password tomorrow. Unspec'd mocks verify nothing about the interface they impersonate [L3].

3.7 Loop-asserts in API tests

tests/integration/test_health.py:40-44 loops over dependencies asserting four fields each. Legible, but a failure names no dependency; unroll or include dep["name"] in each assert message [L2: failures must self-explain]. Minor.

Addendum — second-pass findings (CI & pipeline deep-dive)

The first pass audited the suite; this pass audits what happens around it. Six additional findings, several more severe than anything in §3.

A1. A database-requiring test sits in the unit layer and never executes in CI

tests/unit/test_schema_orm_matches_database.py carries @pytest.mark.requires_db. Trace its execution through the pipeline:

addopts = ["-m", "not integration and not requires_db"]   # pyproject.toml

CI step 1:  pytest tests/            → excludes requires_db  (skipped)
CI step 2:  pytest tests/ -m integration  → selects ONLY integration
                                          → requires_db-only test excluded again

Both marker expressions miss it. The ORM-matches-database invariant — precisely the check that catches schema drift — runs on zero CI executions. It's also misfiled: a live-database test in the tests/unit/ directory contradicts both its marker and L4's boundary rule.

A2. Marker discipline is directory-based, not declared — selection is unreliable

Of 66 test files, roughly a dozen carry any explicit pytest.mark.unit/integration; the rest rely on their directory name. But markers are what CI selects by, and directories are what humans navigate by — when they disagree (see A1), configuration silently wins. You also have --strict-markers enforcing marker validity, nothing enforcing marker presence.

A3. The suite effectively runs twice per CI invocation

test.yml executes three pytest steps: default run (unit+property), integration run, then a coverage run repeating the default set with --cov=src. Unit tests execute twice every push. On a suite containing sleeps (§3.1) that's pure paid latency.

A4. No timeout plugin — one hung async test burns the whole job

The job has a 30-minute ceiling but nothing fails a wedged test. This repo's own history makes the risk concrete: websocket/async code paths are heavily tested here, and async hangs characteristically produce no exception — just silence until the job dies without a useful report. pytest-timeout (e.g., --timeout=60) converts an opaque job-death into a named failing test.

A5. Small workflow defects compounding quietly

  • Coverage artifact references a report never generated: the archive step uploads htmlcov/, but the coverage run produces only lcov + term-missing — no --cov-report=html. The artifact is permanently half-empty.
  • Cache key omits uv.lock: keyed on hashFiles('pyproject.toml') only; lockfile-only changes restore stale caches (uv self-heals, so cost = time, not correctness).
  • No concurrency group: push + PR of the same branch run duplicate full jobs.
  • Migrations run before lint: services spin up and alembic runs before ruff/ty — a lint typo discovered in minute 4 costs the service-startup overhead of minutes 0–4. Cheap checks should gate expensive ones [L9 ordering].
  • factory-boy installed but unused: make_mock_user() hand-rolls what your existing dependency builds properly — factories give spec'd, varied fixtures for free.

A6. Positive additions to §2 worth naming

  • All three backing services in CI carry proper health checks with retries (test.yml:19-52) — textbook service provisioning.
  • alembic upgrade head runs in CI before tests — migration chain verified continuously (and test_migration_chain.py guards it at unit level too).
  • hypothesis-powered property tests exist for credit invariants — most professional suites never reach this.

  2. P0 — Add pytest-timeout with 60s default (A4).
