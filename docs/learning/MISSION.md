# Mission

**Master software testing so that software ships reliably to real customers — and think about test strategy the way senior engineers do.**

## Goals (in priority order)

1. **Ship reliable products.** Use tests so that software used by real customers behaves predictably — catch regressions before users do, and know what safety net exists when things break in production.
2. **Senior-level judgment.** Move beyond "writing some tests" toward strategic thinking: which kinds of tests belong where, what *not* to test, how much test investment earns its keep.
3. **Career strength.** Testing fluency is a skill gap that shows up at work and in interviews; close it deliberately.
4. **Apply to real projects.** Transfer everything learned directly onto real codebases (including AgentNexus) once the universal principles are solid.

## Constraints & preferences

- **Level:** Beginner — knows basic asserts exist; no fluent grasp of mocking, fixtures, or strategy yet.
- **Stack:** Generic/universal examples. Language-agnostic principles first; project-specific application comes later.
- **Pace:** Short lessons (~10 min), one tightly-scoped topic per session.
- **Method:** Retrieval practice quizzes in every lesson; interleaved review as topics accumulate.

## Definition of success

The learner can look at an unfamiliar codebase and confidently answer:
- What should be tested here, and at which level?
- What should deliberately be left untested?
- Which anti-patterns is this suite suffering from?
- How would this suite translate into reliability for paying customers?
