This video details the final stages of a compiler's pipeline, specifically **Code Generation**, where intermediate representation (IR) is transformed into machine code. The narrator explains that because perfect optimization of variables, instructions, and scheduling is mathematically intractable (NP-complete or undecidable), compilers rely on sophisticated heuristics.

### **Key Stages of Code Generation**

*   **Instruction Selection (5:10 - 7:05):** The compiler selects the best machine-specific instructions to implement IR operations. This is framed as a **tiling problem**, where the compiler covers an IR expression tree with the cheapest possible machine instruction "tiles." CISC architectures, like x86, make this complex because they offer powerful instructions that can perform multiple IR operations (like load-compute-store) in one step.

*   **Register Allocation (8:31 - 11:05):** Given the limited number of physical CPU registers, the compiler must map an infinite supply of virtual variables to these registers. This is treated as a **graph coloring problem**, where variables that are "live" simultaneously (and thus conflict) must be assigned different registers. If the compiler runs out of registers, it must "spill" values to memory. Just-in-Time (JIT) compilers often use a faster but slightly less efficient method called **linear scan** instead of full graph coloring.

*   **Instruction Ordering (11:05 - 13:26):** To prevent processor stalls in pipelined CPUs, the compiler schedules instructions to ensure the processor remains busy. By pulling independent instructions forward, the compiler hides latency caused by memory access. While modern hardware with out-of-order execution hides some of this, compiler-level scheduling remains critical for simpler "in-order" cores found in microcontrollers.

*   **Stack Frames & Calling Conventions (13:26 - 16:08):** To support recursion and local variables, the compiler generates **stack frames** (activation records). The **calling convention** (e.g., System V AMD64) establishes a contract between the caller and the callee, dictating how arguments are passed (often in specific registers like RDI, RSI), how the return value is handled (RAX), and which registers are "caller-saved" versus "callee-saved" to prevent data loss across function boundaries.

*   **Peephole Optimization (16:08 - 17:33):** This final, local pass scans the generated machine code through a small "sliding window" to perform micro-optimizations, such as replacing `xor %rax, %rax` to zero a register or converting multiplications by powers of two into faster bitwise shifts. It acts as a necessary cleanup stage that catches inefficiencies created during the previous lowering steps.
The video explains that register allocation is **NP-complete** because it requires mapping an infinite number of virtual variables to a limited number of physical CPU registers. This task is modeled as **graph coloring**, where each variable is a node and an edge exists between two variables if they are "live" at the same time and thus conflict. Assigning registers effectively means coloring the graph so that no two connected nodes share the same color, a problem that is known to be computationally intractable (09:21 - 10:14).
